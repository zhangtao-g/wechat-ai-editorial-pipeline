# 选题与真实性规则

规则文件在 `templates/hot-editorial-policy.md`，那是最终依据。本文解释这些规则为什么这么定，以及执行时怎么判断边界。

---

## 1. 账号定位

**帮普通人看懂 AI 新变化，判断哪些值得用、值得花钱、值得关注。**

不是 AI 技术媒体，不是模型评测机构，也不是投资号。读者大多不是开发者，他们关心的是：

- 这东西对我有什么用；
- 要不要花钱；
- 会不会影响我的工作、隐私、孩子教育；
- 别人用了效果怎么样，有没有坑。

所以选题的第一标准不是「技术重要性」，而是**读者相关性**。

---

## 2. 选题优先级

每天按顺序找，上一档有合格选题就不跳到下一档：

1. **DeepSeek**：官方或经证实的模型、API、定价、开源、合作、团队与生态变动；
2. **腾讯 WorkBuddy**（腾讯龙虾）：版本、定价与 Credits、专家/Skills 市场、企微/微信接入、企业落地；
3. **其他国内 AI**：通义千问、豆包、Kimi、智谱 GLM、MiniMax、混元、文心、可灵、即梦等；
4. **海外精选**：OpenAI / Anthropic / Google 等，占比约 20%。

### 为什么是这个顺序

- DeepSeek 是国内 AI 讨论的中心，价格、开源、模型迭代都能直接影响普通用户和开发者；
- WorkBuddy 是办公场景，和「打工人」读者高度相关；
- 其他国产模型覆盖长尾需求；
- 海外消息有信息增量，但对国内读者的直接决策影响较弱，所以控制在 20% 左右。

### 优先级不降低门槛

如果 DeepSeek 当天只有传闻、旧闻、已写事件、没有原文证据 → **视同该档没有合格选题**，顺延到下一档。

不许为了「优先 DeepSeek」硬发一条没有新事实的稿子。

---

## 3. 什么值得写

### 优先

- 官方发布、正式上线、价格调整、开源、重大合作；
- 有具体数字和可验证结果的产品更新；
- 真实用户/创作者的探索、对比、失败案例；
- 与普通人工作、生活、隐私、教育、就业直接相关的变化；
- 有争议但能核实双方说法的事件。

### 不写

- 纯技术评测（除非能落到「普通人要不要用」）；
- 模型跑分堆砌，没有场景；
- 未经证实的传闻当官宣；
- 旧闻换标题重发；
- 只有二手摘要、拿不到原文的事件；
- 招聘、融资、股价类没有公众影响的新闻；
- 洗稿、全文翻译、结构照搬。

### 破圈公式

```text
AI + 全民话题 = 破圈
```

已验证有效的结构：

- 「我用 AI 做了 XX 让人惊讶的事」；
- 「AI 帮我发现了 XX 规律」；
- 「科技巨头 + 隐私侵犯 + 具体数字」；
- 「AI Agent 为自己做了 X」。

反例：纯模型对比、架构分析、benchmark 排名——受众窄，阅读低，不涨粉。

---

## 4. 证据分级

每条关键事实必须标注来源类型和核验状态。

| 级别 | 来源 | 用法 |
|---|---|---|
| A | 官方博客、官方文档、价格页、GitHub release、论文原文、监管文件 | 可以直接作为事实 |
| B | 具名媒体（有记者、有编辑、有原文链接） | 可以作为事实，但要注明「据 XX 报道」 |
| C | 创作者原帖、实测、开源项目 | 可以引用，但要注明「作者测试/演示」，不能写成我们亲测 |
| D | 聚合站、转载、匿名截图、群聊 | 只能作为线索，不能独立支撑成稿 |
| E | 传闻、爆料、疑似 | 只能写 rumor_check，标题和正文都要体现不确定性 |

### 核验状态

- `confirmed`：至少一个 A 级来源，或两个独立 B 级来源；
- `unverified`：只有 C/D 级来源，或关键数字对不上；
- `refuted`：已被官方或多家媒体否认。

`unverified` 不能写成既定事实。`refuted` 不能写。

---

## 5. 传闻处理

传闻可以写，但必须：

- 标题体现不确定性：「据传」「疑似」「爆料称」；
- 正文区分「已确认」「技术线索」「匿名消息」；
- 不用「官宣」「正式发布」「确定」；
- 给出反方证据或官方沉默的事实；
- 不用匿名截图作为唯一证据。

代码痕迹不证明正式发布；多个转载不等于独立证实；招聘信息不证明产品上线。

---

## 6. 创作者研究

重点关注有原始探索的博主：实际测试、可复现工作流、新玩法、开源项目、能力边界、失败案例。

引用规则：

- 必须找到原帖，核验账号身份和发布时间；
- 记录作者、原帖 URL、发布时间、任务条件、结果、局限；
- 优先独立复现；不能复现时，明确写「作者测试/演示」；
- 保留作者、原帖、图片归属；
- 遵守作者的转载限制；
- 不全文翻译，不结构照搬，不洗稿。

### 实测 vs 资料调研

| 类型 | 条件 | 能写什么 | 不能写什么 |
|---|---|---|---|
| 真实测试 `hands_on` / `comparison_test` | 有账号/API/浏览器权限，实际跑过，保存原始输出 | 运行时间、环境、输入输出、失败、返工、成本 | 没跑过的结论 |
| 资料调研 `comparison_analysis` | 只读公开资料 | 官方数据、公开演示、独立案例 | 「我亲自用了」「我省了多少时间」「我测出准确率」 |

实测稿必须有 `testing-evidence.json`：

```json
{
  "task": "具体任务",
  "tested_at": "ISO 时间",
  "method": "方法、提示词、次数",
  "runs": [
    {
      "model": "模型名",
      "version": "确切版本",
      "access": "web / API / 本地",
      "settings": "联网、推理、温度等",
      "prompt_path": "绝对路径",
      "output_path": "绝对路径",
      "output_sha256": "哈希"
    }
  ]
}
```

`comparison_test` 至少 2 个不同模型；`hands_on` 至少 1 个。路径必须在本次研究目录内，输出哈希必须匹配。

没有原始输出，就不能叫实测。

## 7. 标题规则

- 必须点名具体公司、机构、人物或产品；
- 说清它做了什么；
- 不用「AI 巨头」「某公司」「新模型」「刚刚发布」让读者猜；
- 不设人为字数/字节上限；
- 钩子放在前 10 字；
- 数字、型号、版本、对标对象必须能在原文找到；
- 不制造绝对赢家（对比类）；
- 不拼接正文没有的事实。

### 标题与正文范围一致

正文讲整个办公场景，标题只写「PPT」→ 读者进来觉得跑题。
正文讲一个例子，标题却概括全部 → 过度承诺。

合格结构：

```text
主体（公司/产品/人物）+ 具体载体 + 反差动作
```

例：

- 「DeepSeek 把 API 价格砍到 1/10，谁在买单」
- 「我妈用 AI 写的第一份简历，比我写得好」
- 「同一个任务，Claude 花了 3 分钟，它花了 3 小时」

---

## 8. 配额与节奏

- 热点：每天 1 篇，重大独立消息可追加 1 篇，硬上限 2 篇；
- 日报：每天 1 篇，10–16 条；
- 周总结：每周 1 篇；
- 没有合格内容允许空缺，20:00 兜底也不硬凑；
- 同一事件不反复写；真正的新进展必须有独立一手事实。

---

## 9. 反同质化

### 常见同质化

- 每篇都是「发布 → 参数 → 对比 → 结论」；
- 开头都是「随着 AI 的发展」；
- 结尾都是「让我们拭目以待」；
- 每个观点都配三点论据；
- 标题都是「XX 发布了 YY，意味着什么」。

### 解法

- 换叙事入口：从一个人、一个场景、一个失败开始；
- 换结构：有的稿子只讲一个细节，不铺全景；
- 换证据：多用一手体验、原始数据、具体对话；
- 换语气：承认不知道、承认失败、承认利益冲突；
- 换结尾：给一个具体动作，不给宏大判断。

---

## 10. 发布前检查清单

### 选题与事实

- [ ] 主体明确，标题点名；
- [ ] 事件在 48 小时内（创作者研究 14 天内）；
- [ ] 每个关键数字能在原文找到；
- [ ] 传闻有不确定性标注；
- [ ] 没有把 C/D 级来源写成 A 级事实；
- [ ] 实测稿有 `testing-evidence.json` 和输出哈希；
- [ ] 资料调研稿没有伪装成亲测。

### 内容

- [ ] 1500–2000 字；
- [ ] 第一人称，口语化；
- [ ] 有具体场景、数字、失败；
- [ ] 没有教科书式列表和加粗金句；
- [ ] 没有投资分析；
- [ ] 正文没有重复总标题。

### 合规

- [ ] 敏感词扫描清零；
- [ ] 无政治/历史/领土风险；
- [ ] 无金融承诺、荐股；
- [ ] 无医疗功效；
- [ ] 无未证实指控；
- [ ] 图片版权清晰。

### 排版与上传

- [ ] `<img>` 数 = `图N｜` 数；
- [ ] 封面 1880×800；
- [ ] 摘要 ≤70 字节；
- [ ] 无本地路径；
- [ ] `draft/get` 六项全过；
- [ ] 通知已发或入队。
